`rollout.ts` exporta preflight (solo lectura), backfill (mapa commerce→location explícito cuando no hay exactamente un activo), contract (requiere SHA desplegado real y confirmación writers retirados). No emitir consumos de órdenes históricas.

Operación: snapshot autorizado → expand/puente → preflight → mapa si necesario → backfill/validación → desplegar nuevo SHA con flag OFF → comprobar writers/locales/revisiones → habilitar flag únicamente para nuevos cierres → drenar/retirar writers antiguos → contract. Cada operación PROD/push necesita autorización nueva. Owner configura cron-job.org 0/30, 24 h America/Guayaquil; autorización del secreto antes de DB.

Contract es SQL operativo deliberadamente separado del journal expand. Conserva eventos, revisiones y movimientos; no borra consumos para rollback. El código nuevo no lee costo global tras contract; schema legado mantiene declaración solo durante convivencia, próxima migración snapshot debe representar contract autorizado antes de generar otro SQL. Rollback después de habilitar no recrea historia ni elimina eventos.
