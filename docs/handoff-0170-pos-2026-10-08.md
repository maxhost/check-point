## Archivos y comportamiento

- `apps/merchant/src/app/backoffice/pos/**`: página con permiso pos y locales activos;
  consola, catálogo/carrito, cupón, cobro y ticket. Todo usa el kit existente, colores
  semánticos y utilidades Tailwind; no hay CSS, kit, API ni servidor modificados.
- `backoffice/settings/**`: Cuenta → Configuración → Activar/Desactivar POS, exclusivo owner;
  modal con openCount cuando hay órdenes abiertas.
- Navegación: POS bajo Mi negocio/Administración, solo módulo encendido y permiso pos.
  La sesión HTTP informa posEnabled (el guard de servidor actual no expone ese campo).
- Equipo: toggle POS condicionado al módulo; escritura no envía el permiso oculto con módulo apagado.
- Layout/navegación: aislamiento de impresión con variantes print. La regla global de afiches
  pone body invisible; el ticket usa print:visible para recuperar la impresión sin CSS nuevo.
- `tests/e2e/pos.spec.ts`, `tests/e2e/support/pos-counter-harness.tsx`: navegador con UI y CSS reales,
  respuestas HTTP simuladas. El lector de cámara importado es el del mostrador; los tests usan
  la alternativa de pegar un código leído por lector QR. No se alteró el mostrador.

Los snapshots viejos se envían con lineId; agregar el mismo producto desde el catálogo genera
una línea nueva con el precio actual, conservando las anteriores. Productos sin precio exigen
importe. Version conflict reemplaza el borrador por la orden vigente y muestra aviso.
No se agrega automáticamente un producto del cupón a una mesa ya guardada: la pantalla pide
editar la orden si falta el producto fijo. Oferta libre permite elegir una línea guardada.
El veredicto y resultado definitivo vienen del servidor; la calculadora usa la misma función
informativa de neto del mostrador. Recibido/cambio nunca se envían.
Cierre congela cuerpo y UUID ante errores de transporte o 5xx. Reintentar devuelve la misma
venta; errores HTTP definitivos permiten corregir y comenzar otro intento.
